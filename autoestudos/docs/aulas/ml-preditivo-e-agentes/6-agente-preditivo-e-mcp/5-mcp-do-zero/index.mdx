Até aqui, a sua tool funciona dentro do seu processo Python. A persona sintética da Galaxies não vive nele. Ela é uma aplicação de outro time, com o próprio LLM, as próprias regras e um cliente <Termo id="mcp">MCP</Termo> que vai se conectar ao seu servidor, perguntar o que ele oferece e chamar a previsão quando achar necessário.

Isso inverte a posição de quem escreve a tool. Você não controla o prompt da persona, não sabe qual modelo ela usa e não vê a conversa. O que você controla é o que o servidor **anuncia** (nomes, descrições, *schemas*, instruções) e o que ele **devolve** (dados tipados, erros legíveis). Tudo o que as aulas anteriores construíram (contrato, função pura, erros que dizem o que fazer) é o que torna esse servidor usável por um LLM que você nunca vai conhecer.

:::info[A ideia central]
Um **servidor MCP** anuncia **tools**, **resources** e **prompts** num formato padrão (JSON-RPC 2.0), e qualquer **host** com LLM consegue usá-los através de um **cliente**. O servidor da trilha é um adaptador fino: cada tool chama `api.prever_criativo` ou `api.comparar_criativos`, o *schema* vem do contrato Pydantic e a saída estruturada é o próprio `PredictionResponse`. **Não coloque um LLM no servidor**: o LLM já está do lado do cliente.
:::

## Host, cliente e servidor

O vocabulário do MCP separa três papéis:

- **Host**: a aplicação com o LLM. A persona da Galaxies, o Claude Desktop, o Claude Code ou o seu agente LangGraph.
- **Cliente**: o componente, dentro do host, que mantém a conexão com **um** servidor. Um host conectado a três servidores tem três clientes.
- **Servidor**: o programa que expõe capacidades. O seu é o `galaxies-preditor`.

O servidor oferece três primitivas, com donos diferentes:

| Primitiva | Quem decide usar | No projeto |
| :--- | :--- | :--- |
| **Tools** | O LLM do host (*model-controlled*) | `prever_criativo`, `comparar_criativos` |
| **Resources** | A aplicação do host, para dar contexto (*application-controlled*) | `model://card` (versão, métricas, limites) e os *schemas* |
| **Prompts** | O usuário, como modelos prontos (*user-controlled*) | `decidir_entre_criativos` |

## stdio ou Streamable HTTP

São dois transportes para as mesmas mensagens:

| | stdio | Streamable HTTP |
| :--- | :--- | :--- |
| Como conecta | O host **inicia** o servidor como subprocesso e conversa pela entrada e saída padrão | O servidor já está no ar; o cliente faz POST num endpoint (`/mcp` no FastMCP) |
| Quando usar | Local: Claude Desktop, Claude Code, testes, demo | Remoto: vários clientes, servidor compartilhado |
| Cuidado principal | **Nada pode ir para o stdout** além do JSON-RPC | Autenticação e exposição na rede |

Para a entrega, pergunte à Galaxies como a persona vai se conectar. Se for stdio, ela precisa conseguir rodar o seu servidor na máquina dela (o README vira crítico). Se for HTTP, você precisa hospedar o servidor.

## A spec 2026-07-28 e a "era" do seu servidor

A revisão vigente da especificação é a **2026-07-28**, e ela mudou algo fundamental: o MCP ficou **stateless**. O *handshake* `initialize` saiu; cada requisição carrega a versão do protocolo e as capacidades do cliente no campo `_meta`; os servidores **devem** implementar um método novo, `server/discover`; e as sessões do Streamable HTTP (o cabeçalho `Mcp-Session-Id`) foram removidas. A spec chama as versões com `initialize` (2025-11-25 e anteriores) de **era legada**, as novas de **era moderna**, e define implementações de **duas eras** (*dual-era*).

O stack desta trilha (`mcp==1.30.0` e `fastmcp==3.4.7`) fala a **era legada**: o servidor abaixo, testado no MCP Inspector, responde ao `initialize` com `protocolVersion: 2025-11-25`. Pela matriz de compatibilidade da spec, um cliente **moderno** só consegue falar com um servidor legado se implementar o *fallback* previsto (no stdio, sondar com `server/discover` e cair para o `initialize`). Clientes legados e clientes de duas eras funcionam.

Duas consequências práticas:

1. **Pergunte à Galaxies qual era o cliente da persona fala.** Se for legado ou de duas eras, o seu servidor funciona como está.
2. **Não "atualize para a spec nova" trocando os pacotes.** É aí que entra a pegadinha de versões.

:::danger[A pegadinha de versões: FastMCP 4 e mcp 2]
Existem o **FastMCP 4.x** (lançado em ago/2026) e o **SDK oficial `mcp` 2.x**, em que a classe `FastMCP` foi renomeada para `MCPServer`, sem alias. Os dois são incompatíveis com o **`langchain-mcp-adapters` 0.3.2**, que declara `mcp<2.0.0,>=1.24.0` nas dependências (e o `fastmcp` 3.4.7 também exige `mcp<2.0`). Instalar qualquer um dos dois quebra o lado LangGraph do projeto.

O próprio FastMCP 3.4.7, ao iniciar, imprime um aviso tentador: `Update available: 4.0.10. Run: pip install --upgrade fastmcp` (saída real no nosso ambiente). **Não siga.** Fixe as versões no `pyproject.toml` (`fastmcp==3.4.7`, `mcp==1.30.0`, `langchain-mcp-adapters==0.3.2`), como no bloco de ambiente da [aula 6.1](/aulas/ml-preditivo-e-agentes/agente-preditivo-e-mcp/o-llm-orquestra-o-modelo-preve).
:::

## O servidor

O servidor tem duas partes: as tools e os resources, mais o ponto de entrada.

```python
# galaxies_tool/servidor_mcp.py — parte 1: o servidor e as tools
import sys
from typing import Annotated

from fastmcp import FastMCP
from fastmcp.exceptions import ToolError
from langchain_core.tools import ToolException
from pydantic import Field

from galaxies_tool import api
from galaxies_tool.modelo import carregar_modelo
from galaxies_tool.schemas import PredictionRequest, PredictionResponse

mcp = FastMCP(
    "galaxies-preditor",
    version="0.1.0",
    instructions=("Prevê curtidas de YouTube Shorts (moda, beleza, automotivo) ANTES da "
                  "publicação. O número vem de um modelo treinado: repasse-o sem alterar, "
                  "sempre com o intervalo de 80% e a confiança. Limites em model://card."),
)
SOMENTE_LEITURA = {"readOnlyHint": True, "idempotentHint": True, "openWorldHint": False}


@mcp.tool(annotations=SOMENTE_LEITURA, timeout=120)
def prever_criativo(pedido: PredictionRequest) -> PredictionResponse:
    """Prevê as curtidas de UM Short antes da publicação: mediana, intervalo de 80%,
    confiança, fatores (SHAP), comparáveis e a versão do modelo."""
    try:
        return api.prever_criativo(pedido)
    except ToolException as e:  # erro "de negócio": mensagem clara para o LLM do cliente
        raise ToolError(str(e)) from e


@mcp.tool(annotations=SOMENTE_LEITURA, timeout=300)
def comparar_criativos(
    criativos: Annotated[dict[str, PredictionRequest],
                         Field(min_length=2, max_length=10, description="Nome curto -> pedido.")],
) -> dict:
    """Compara 2 a 10 criativos: ranking, intervalos e P(A supera B) para cada par."""
    try:
        return api.comparar_criativos(criativos)
    except ToolException as e:
        raise ToolError(str(e)) from e
```

O que cada detalhe faz:

- **`instructions`** vai para o host no início da conexão. É o lugar para dizer ao LLM da persona que o número vem de um modelo e não deve ser alterado.
- **O parâmetro `pedido: PredictionRequest`** vira o `inputSchema` da tool. A descrição de cada campo, os `Literal` e o exemplo de data com fuso chegam ao LLM do outro lado.
- **O retorno `-> PredictionResponse`** faz o FastMCP publicar um `outputSchema` e devolver o resultado também como `structuredContent`, que é JSON tipado, além do texto. Um host que valida saídas consegue conferir o contrato sem parsear texto.
- **`annotations`** informam ao host que a tool só lê, é idempotente e não acessa o mundo externo (`readOnlyHint`, `idempotentHint`, `openWorldHint`). São dicas para o host decidir, por exemplo, se pede confirmação ao usuário.
- **`timeout`** limita o tempo de cada chamada no servidor.
- **`ToolError`** transforma um erro de negócio (canal fora da base) numa resposta `isError` com a mensagem legível. Erros de validação do Pydantic viram erro de tool automaticamente.

```python
# galaxies_tool/servidor_mcp.py — parte 2: resources (model card e esquemas) e execução
@mcp.resource("model://card", mime_type="application/json")
def model_card() -> dict:
    """Versão, features, métricas do teste temporal e limites do modelo."""
    b = carregar_modelo()
    return {"versao": b.versao, "alvo": "log(curtidas+1) relativo à mediana recente do canal",
            "features": b.features, "metricas_teste_temporal": b.metricas,
            "intervalo": "80%, regressão quantílica + ajuste conformal (CQR)",
            "limites": ["base SINTÉTICA de demonstração", "Shorts de moda, beleza e automotivo",
                        "prevê curtidas, não views", "não conhece tendências após o treino"]}


@mcp.resource("schema://prediction-request", mime_type="application/json")
def esquema_entrada() -> dict:
    return PredictionRequest.model_json_schema()


@mcp.resource("schema://prediction-response", mime_type="application/json")
def esquema_saida() -> dict:
    return PredictionResponse.model_json_schema()


@mcp.prompt
def decidir_entre_criativos(marca: str) -> str:
    """Roteiro para o LLM do cliente comparar criativos de uma marca."""
    return (f"Você assessora a marca {marca}. Chame comparar_criativos com os criativos "
            "enviados, apresente o ranking com intervalos e P(A supera B) e diga, em uma "
            "frase, o que mais pesou. Não altere nenhum número.")


if __name__ == "__main__":
    api.aquecer()  # modelo, índice e SHAP na memória antes da 1ª chamada
    if "--http" in sys.argv:
        mcp.run(transport="http", host="127.0.0.1", port=8000)  # Streamable HTTP em /mcp
    else:
        mcp.run(show_banner=False)  # stdio: NUNCA dê print() (stdout é o canal JSON-RPC)
```

O *resource* `model://card` responde à pergunta que todo consumidor sério faz antes de confiar num número: **qual modelo é esse, medido como, e onde ele não funciona**. O `api.aquecer()` carrega modelo, índice e SHAP antes da primeira chamada. E o comentário do `mcp.run` não é enfeite: num servidor stdio, **qualquer `print()` no stdout corrompe o protocolo**. Logs vão para o stderr (o `logging` do Python já faz isso por padrão), e o banner do FastMCP fica desligado com `show_banner=False`.

Para rodar:

```bash
python -m galaxies_tool.servidor_mcp          # stdio (quem inicia é o host)
python -m galaxies_tool.servidor_mcp --http   # Streamable HTTP em http://127.0.0.1:8000/mcp
```

## Testar em memória, sem processo e sem rede

O `fastmcp.Client` aceita o próprio objeto `FastMCP` como transporte. O cliente e o servidor rodam no mesmo processo, mas conversam pelo protocolo MCP de verdade: `initialize`, `tools/list`, `tools/call`.

```python
# rodar_mcp_memoria.py — o servidor visto por um cliente MCP, sem processo e sem rede
import asyncio
import json

from fastmcp import Client

from galaxies_tool.servidor_mcp import mcp

B = {"creative": "lumina_b.mp4", "caption": "1 produto, 20 segundos #antesedepois #maquiagem",
     "planned_datetime": "2026-10-01T19:00:00-03:00", "channel_id": "UC_lumina_beauty",
     "sector": "beleza"}


async def main():
    async with Client(mcp) as cliente:  # transporte em memória
        for t in await cliente.list_tools():
            print("tool:", t.name, "| args:", list(t.inputSchema["properties"]),
                  "| outputSchema:", t.outputSchema is not None,
                  "| readOnly:", t.annotations.readOnlyHint)
        print("resources:", [str(r.uri) for r in await cliente.list_resources()])
        print("prompts:", [p.name for p in await cliente.list_prompts()])
        r = await cliente.call_tool("prever_criativo", {"pedido": B})
        sc = r.structured_content
        print("previsão:", sc["predicted_metric"], sc["interval_low"], sc["interval_high"],
              sc["confidence_flag"], sc["model_version"])
        card = json.loads((await cliente.read_resource("model://card"))[0].text)
        print("model card:", card["versao"], {k: round(v, 3) for k, v in
                                               card["metricas_teste_temporal"].items()})
        ruim = B | {"planned_datetime": "2026-10-01T19:00:00"}
        erro = await cliente.call_tool("prever_criativo", {"pedido": ruim}, raise_on_error=False)
        print("erro:", erro.is_error, erro.content[0].text.splitlines()[1:3])


asyncio.run(main())
```

O mesmo vira teste automatizado. O `pytest` não precisa do `pytest-asyncio`: o plugin do `anyio`, que já vem instalado como dependência do stack, roda testes marcados com `@pytest.mark.anyio`, e a *fixture* `anyio_backend` no `conftest.py` fixa o backend `asyncio`.

```python
# tests/test_mcp.py — o servidor MCP, testado em memória (sem processo, sem rede)
import pytest
from fastmcp import Client

from galaxies_tool.api import prever_criativo
from galaxies_tool.schemas import PredictionResponse
from galaxies_tool.servidor_mcp import mcp


@pytest.mark.anyio
async def test_servidor_publica_tools_e_resources():
    async with Client(mcp) as cliente:
        assert {t.name for t in await cliente.list_tools()} == {"prever_criativo",
                                                                 "comparar_criativos"}
        uris = {str(r.uri) for r in await cliente.list_resources()}
        assert {"model://card", "schema://prediction-request"} <= uris


@pytest.mark.anyio
async def test_mcp_devolve_o_mesmo_que_a_funcao(pedido_b):
    async with Client(mcp) as cliente:
        r = await cliente.call_tool("prever_criativo", {"pedido": pedido_b.model_dump(mode="json")})
    resposta = PredictionResponse.model_validate(r.structured_content)
    assert resposta == prever_criativo(pedido_b)


@pytest.mark.anyio
async def test_pedido_sem_fuso_vira_erro_legivel(pedido_b):
    pedido = pedido_b.model_dump(mode="json") | {"planned_datetime": "2026-10-01T19:00:00"}
    async with Client(mcp) as cliente:
        r = await cliente.call_tool("prever_criativo", {"pedido": pedido}, raise_on_error=False)
    assert r.is_error and "timezone" in r.content[0].text
```

```text

3 passed
```

O segundo teste merece destaque: ele compara a resposta que passou pelo protocolo com a da função pura. Se alguém colocar lógica no adaptador, esse teste quebra.

## MCP Inspector

O **MCP Inspector** é o cliente oficial de depuração. A versão atual (v2) tem três modos: interface web (padrão), `--cli` e `--tui`. Para um servidor stdio, o comando alvo vem logo depois das opções de modo, e as variáveis de ambiente entram com `-e`:

```bash
# interface web: abre no navegador, com as tools, resources e prompts do servidor
npx @modelcontextprotocol/inspector /abs/galaxies-tool/.venv/bin/python \
  /abs/galaxies-tool/galaxies_tool/servidor_mcp.py \
  -e PYTHONPATH=/abs/galaxies-tool -e GALAXIES_ARTEFATOS=/abs/galaxies-tool/artefatos

# CLI: bom para CI e para conferir o handshake
npx @modelcontextprotocol/inspector --cli /abs/galaxies-tool/.venv/bin/python \
  /abs/galaxies-tool/galaxies_tool/servidor_mcp.py \
  -e PYTHONPATH=/abs/galaxies-tool -e GALAXIES_ARTEFATOS=/abs/galaxies-tool/artefatos \
  --method initialize
```

Saída real do modo CLI (trecho):

```json
{
  "serverInfo": {"name": "galaxies-preditor", "version": "0.1.0"},
  "protocolVersion": "2025-11-25",
  "instructions": "Prevê curtidas de YouTube Shorts (moda, beleza, automotivo) ANTES da publicação. O número vem de um modelo treinado: repasse-o sem alterar, sempre com o intervalo de 80% e a confiança. Limites em model://card."
}
```

Duas armadilhas que custaram tempo ao testar esta aula. O Inspector v2 interpreta o `-m` de `python -m galaxies_tool.servidor_mcp` como uma opção dele: por isso o alvo acima é o **caminho do arquivo**, não o módulo. E o processo iniciado **não herda** o seu `PYTHONPATH`: sem o `-e`, o servidor morre com `ModuleNotFoundError` e o Inspector só mostra `Connection closed`.

Para chamar a tool pela CLI, use `--method tools/call --tool-name prever_criativo --tool-arg 'pedido={...}'`, com o pedido em JSON.

## No Claude Desktop e no Claude Code

Os dois são hosts MCP e servem como "persona de teste" antes da entrega. Use **caminhos absolutos**: o host inicia o servidor a partir de outro diretório, e o `artefatos/` relativo não será encontrado. No Claude Desktop, o arquivo `claude_desktop_config.json` (no macOS, em `~/Library/Application Support/Claude/`) recebe:

```json
{
  "mcpServers": {
    "galaxies": {
      "command": "/abs/galaxies-tool/.venv/bin/python",
      "args": ["-m", "galaxies_tool.servidor_mcp"],
      "env": {
        "PYTHONPATH": "/abs/galaxies-tool",
        "GALAXIES_ARTEFATOS": "/abs/galaxies-tool/artefatos"
      }
    }
  }
}
```

No Claude Code, o equivalente é um comando (com `--scope project`, a configuração vai para um `.mcp.json` versionável no repositório):

```bash
claude mcp add --transport stdio \
  --env PYTHONPATH=/abs/galaxies-tool --env GALAXIES_ARTEFATOS=/abs/galaxies-tool/artefatos \
  galaxies -- /abs/galaxies-tool/.venv/bin/python -m galaxies_tool.servidor_mcp
claude mcp list   # mostra o servidor e o status da conexão
```

Esses dois trechos seguem a documentação oficial de cada produto e **não foram executados** neste ambiente; o servidor em si foi testado pelo Inspector e pelos clientes das seções acima.

## Dogfooding: consumindo o seu servidor do LangGraph

A melhor forma de enxergar o servidor como a persona vai enxergá-lo é **consumi-lo** de um agente. O `langchain-mcp-adapters` converte as tools MCP em tools do LangChain:

```python
# rodar_persona_mcp.py — dogfooding: um agente LangGraph consumindo o servidor via stdio
import asyncio
import json
import sys
import time
from pathlib import Path

from langchain.agents import create_agent
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain_mcp_adapters.tools import load_mcp_tools

PROJETO = Path.cwd()
cliente = MultiServerMCPClient({"galaxies": {
    "transport": "stdio", "command": sys.executable,  # o Python do venv do projeto
    "args": ["-m", "galaxies_tool.servidor_mcp"],
    "env": {"GALAXIES_ARTEFATOS": str(PROJETO / "artefatos"), "PYTHONPATH": str(PROJETO)}}})


class FakeComTools(GenericFakeChatModel):  # a "persona" falsa; troque por um LLM real
    def bind_tools(self, tools, **kwargs):
        return self


A = {"creative": "lumina_a.mp4", "caption": "Pele natural em 5 passos #maquiagem #tutorial",
     "planned_datetime": "2026-09-29T14:00:00-03:00", "channel_id": "UC_lumina_beauty",
     "sector": "beleza"}
B = {"creative": "lumina_b.mp4", "caption": "1 produto, 20 segundos #antesedepois #maquiagem",
     "planned_datetime": "2026-10-01T19:00:00-03:00", "channel_id": "UC_lumina_beauty",
     "sector": "beleza"}


async def main():
    t0 = time.perf_counter()
    async with cliente.session("galaxies") as sessao:  # UM processo para todas as chamadas
        tools = await load_mcp_tools(sessao)
        print(f"servidor no ar em {time.perf_counter() - t0:.1f} s; tools:", [t.name for t in tools])
        roteiro = iter([AIMessage("", tool_calls=[{"name": "comparar_criativos", "id": "c1",
                                                   "args": {"criativos": {"A": A, "B": B}}}]),
                        AIMessage("Recomendo o B: P(B > A) = 0,884.")])
        persona = create_agent(FakeComTools(messages=roteiro), tools=tools)
        t0 = time.perf_counter()
        saida = await persona.ainvoke({"messages": [{"role": "user", "content": "A ou B?"}]})
        print(f"pergunta respondida em {time.perf_counter() - t0:.2f} s")
        resultado = json.loads(saida["messages"][2].content[0]["text"])
        print(resultado["ranking"][0], resultado["prob_supera"])
        print(saida["messages"][-1].content)


asyncio.run(main())
```

```text
servidor no ar em 4.9 s; tools: ['prever_criativo', 'comparar_criativos']
pergunta respondida em 0.06 s
{'posicao': 1, 'criativo': 'B', 'predicted_metric': 4237.0, 'interval_low': 1655.0, 'interval_high': 9180.0, 'baixa_confianca': False} {'B > A': 0.884}
Recomendo o B: P(B > A) = 0,884.
```

O detalhe mais importante do código é o `cliente.session("galaxies")`. Sem ele, o `MultiServerMCPClient.get_tools()` cria uma **sessão nova a cada chamada de tool**, e, no stdio, sessão nova significa **processo novo**: o servidor sobe, carrega o modelo e o SHAP, responde e morre. Na nossa máquina, cada chamada levou cerca de 10 s assim, contra cerca de 0,6 s com a sessão reaproveitada (com o servidor já aquecido, a comparação acima levou 0,06 s). Dois outros detalhes: o adapter chama o transporte HTTP de `"streamable_http"` (aceita também `"http"`), e o resultado da tool chega ao LLM como uma lista de blocos de conteúdo com o JSON em texto.

## Erros comuns

:::warning[Armadilhas desta etapa]
1. **`print()` num servidor stdio.** Corrompe o JSON-RPC, e o sintoma costuma ser um erro de conexão genérico. Use `logging` (stderr) e `show_banner=False`.
2. **Caminhos relativos.** O host inicia o servidor de outro diretório. Use caminhos absolutos na configuração e uma variável de ambiente para os artefatos.
3. **Seguir o "Update available" do FastMCP.** O 4.x (e o `mcp` 2.x) quebram o `langchain-mcp-adapters` 0.3.2. Fixe as versões.
4. **Uma sessão por chamada no adapter.** Cada chamada sobe um processo e recarrega o modelo. Use `client.session(...)` + `load_mcp_tools`.
5. **Um LLM dentro do servidor.** O host já tem um. Um segundo LLM no servidor só acrescenta custo, latência e mais um lugar para o número ser alterado.
6. **HTTP aberto na rede sem autenticação.** Para uso local, `127.0.0.1`; para expor, proteja o endpoint.
:::

## Exercício

:::tip[Exercício: um resource template para o histórico do canal]
Antes de pedir uma previsão, a persona às vezes quer saber se o canal está na sua base. Adicione ao servidor um **resource template** `canal://{channel_id}/resumo` que devolva setor, inscritos, número de posts e a mediana de curtidas dos últimos 90 dias da base. Um canal desconhecido deve gerar um erro legível. Teste com o cliente em memória.
:::

<details>
<summary>Ver uma solução</summary>

```python
import pandas as pd
from fastmcp.exceptions import ResourceError

from galaxies_tool.tools import _base_e_indice


@mcp.resource("canal://{channel_id}/resumo", mime_type="application/json")
def resumo_do_canal(channel_id: str) -> dict:
    """Inscritos, número de posts e mediana de curtidas dos últimos 90 dias da base."""
    base, _ = _base_e_indice()
    posts = base[base["channel_id"] == channel_id]
    if posts.empty:
        raise ResourceError(f"canal '{channel_id}' não está na base")
    ultimos = posts[posts["published_at"] >= posts["published_at"].max() - pd.Timedelta(days=90)]
    return {"channel_id": channel_id, "setor": posts["sector"].iloc[-1],
            "inscritos": int(posts["channel_stats_at_collection"].iloc[-1]["subscribers"]),
            "posts_na_base": len(posts),
            "mediana_curtidas_90d": float(ultimos["metric_target"].median()),
            "ultimo_post": posts["published_at"].max().isoformat()}
```

Com o cliente em memória, `await cliente.list_resource_templates()` lista `canal://{channel_id}/resumo`, e a leitura devolve:

```json
{"channel_id": "UC_lumina_beauty", "setor": "beleza", "inscritos": 180000, "posts_na_base": 47, "mediana_curtidas_90d": 2305.0, "ultimo_post": "2026-09-10T22:00:00-03:00"}
```

Para um canal desconhecido, o cliente recebe um `McpError` com a mensagem `canal 'UC_x' não está na base`. Repare que a janela de 90 dias aqui termina no último post da base, e não numa data planejada: é um resumo do histórico, não uma *feature*.

</details>

## Resumo

- **Host** tem o LLM, **cliente** mantém a conexão com um servidor, **servidor** expõe **tools** (o LLM decide), **resources** (contexto) e **prompts** (modelos para o usuário), tudo sobre **JSON-RPC 2.0**.
- **stdio** para uso local (o host inicia o servidor; nada no stdout) e **Streamable HTTP** para servidor remoto em `/mcp`.
- A spec **2026-07-28** é *stateless* (sem `initialize`, com `server/discover`); o nosso stack fala a **era legada** (protocolo 2025-11-25). Confirme a era do cliente da persona.
- Com **FastMCP 3.4.7**, o *schema* vem do contrato Pydantic, a saída vira `structuredContent` e erros viram respostas `isError` legíveis.
- Teste com `fastmcp.Client(mcp)` em memória, depure com o **MCP Inspector**, e faça *dogfooding* com o **`langchain-mcp-adapters`** reaproveitando a sessão. **Fixe** `fastmcp==3.4.7` e `mcp==1.30.0`.
