Copie, cole no seu repositório e preencha. Os templates seguem o que o briefing pede nos entregáveis. Apague as instruções entre `<!-- -->` antes de entregar.

## README

````markdown
# Agente Preditivo de Performance — <seu nome>

> Uma frase: o que o agente faz e para quem.

## 1. Problema e recorte
- **Decisão apoiada:** <!-- quem decide, entre o quê -->
- **Unidade de previsão e momento:** <!-- um Short, antes da publicação -->
- **Alvo:** <!-- log1p(curtidas) ou log(curtidas / mediana anterior do canal); por quê -->
- **Setores:** <!-- pelo menos dois -->
- **Critério de sucesso:** <!-- ex.: par-a-par intra-canal e Spearman acima do baseline em validação temporal -->

## 2. Base de dados
Resumo + link para `docs/DATA_CARD.md`.
- Origem, período dos vídeos, datas de coleta, volume (vídeos/canais/setor)
- Termos de uso e como foram respeitados
- **O que a base não representa**

## 3. Arquitetura
Diagrama + uma frase por componente. Deixe claro que **o número vem do modelo**, não do LLM.

## 4. Instalação e execução
```bash
uv sync
cp .env.example .env         # YOUTUBE_API_KEY, GEMINI_API_KEY...
uv run python -m galaxies_tool.coletar --canais data/canais.csv
uv run python -m galaxies_tool.treinar --config configs/lgbm.yaml
uv run python -m galaxies_tool.servidor_mcp   # servidor MCP (stdio)
uv run pytest
```

## 5. Modelos e configurações
Versões fixadas, hiperparâmetros finais, onde estão os artefatos (MLflow run id).

## 6. Metodologia
Splits (datas de corte), baselines, features por bloco (sem vazamento: como garantiu), incerteza (quantis + conformal), explicabilidade (SHAP + subagente).

## 7. Resultados
| Modelo | MAE (log) | Spearman global | Spearman intra-canal | Par-a-par intra-canal | Cobertura 80% |
|---|---|---|---|---|---|
| Baseline: mediana do canal | | | | | — |
| GBM Opção A (meta + texto) | | | | | |
| + visual | | | | | |
| + VLM | | | | | |

Intervalos de confiança por bootstrap. Comparação com a literatura (Spearman ~0,55–0,85).

## 8. Limitações
Onde o modelo erra (análise de erros), vieses da base, riscos de uso.

## 9. Evolução
O que faria com mais 4 semanas.
````

````markdown
# Experimento <n>: <título curto>
````

## Roteiro de demonstração (5 a 7 minutos)

| Tempo | O que mostrar | Dica |
| :--- | :--- | :--- |
| 0:00 | O problema em uma frase + a pergunta norteadora | Use o caso da marca, não a arquitetura |
| 0:40 | A base: volume, setores, o que não representa | Mostre o data card rapidamente |
| 1:20 | Baseline vs. modelo, com métricas de **ordenação** | Uma tabela; destaque o ganho sobre o baseline |
| 2:10 | Ganho (ou não) da camada multimodal | Com intervalo de confiança |
| 3:00 | **Ao vivo:** 3 criativos de canais fora do treino | Previsão, intervalo, ranking e explicação vs. o valor real ("de-para") |
| 4:30 | Chamando pelo MCP (Inspector ou um cliente) | Mostre que é uma tool consumível |
| 5:30 | Limitações e próximos passos | Honestidade conta pontos |

:::warning[Tenha um plano B]
Grave um vídeo da demo funcionando. APIs gratuitas podem estourar a cota ou cair no dia. Deixe também as respostas da tool salvas em JSON para mostrar se a chamada ao vivo falhar.
:::
